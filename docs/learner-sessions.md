# Observe the learning experience

Status: prepared protocol; no first-time learner observations recorded yet. This document does not certify usability or accessibility.

## Participants and task

Start with a small group including people new to terminals and developers new to Linux. Use supported Linux computers with ordinary terminal settings. Ask each person to install the public binary, open the first lesson, explain the task, complete it, and reopen the app later. Provide the public installation guide. Do not explain shortcuts in advance.

Observe whether the learner discovers Read and Do, recognizes the workspace root, inspects output, finds hints, understands feedback, and knows how to return from Bash. Invite a harmless misplaced report and observe recovery. Ask the learner to solve the related handoff task using changed data.

Record concrete behavior, the application version, Linux distribution, terminal, terminal size, and any help given. Do not record private shell history or unrelated files. Ask permission before recording a person's screen.

## Session record

For each session record install success, first exercise completion, independently explained concepts, follow-up outcome, recovery outcome, and restart outcome. Write the learner's wording for confusing instructions. Link each actionable finding to a roadmap issue with a reproduction and acceptance criterion.

Screen-reader sessions need actual assistive technology and a person comfortable using it. Record which plain and full-screen workflows were tried, focus/announcement problems, and the fixes verified afterward. Color-free terminal tests alone do not satisfy this gate.

## Release decision

POLISH-02 remains unchecked until real sessions occur. Engineering releases may describe tested behavior and outstanding human validation, but must not claim beginner or screen-reader validation based only on an automated rehearsal.
